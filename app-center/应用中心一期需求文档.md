# HiTouch AI 中台应用中心一期 MVP 需求文档

## 1. 文档说明

- 文档状态：产品范围已确认，提交研发评审
- 适用范围：应用中心一期 MVP（P0）
- 目标开发周期：2～3 个工作日，最终排期由研发评估
- 整理日期：2026-07-24
- 原始基线：2026-07-21 版应用中心完整一期需求
- 拆分依据：`docs/superpowers/specs/2026-07-24-app-center-two-phase-scope-design.md`

本文只描述应用中心第一期 MVP。被移出的能力统一进入《应用中心二期需求文档》，不得在研发实现中静默删除本文验收项。

## 2. 背景与 MVP 目标

产品部会通过 HiTouch/Hermes 制作解决具体业务问题的 HTML 小工具。当前缺少统一入口让作者沉淀成果，也缺少让内部同事发现、在线使用并反馈价值的应用中心。

受开发周期限制，第一期只验证最核心的“发布—发现—使用—价值反馈”闭环：

1. 作者能够从 Hermes Session 已产出的 HTML 页面发起发布。
2. 已登录内部同事能够在应用中心找到并在线使用应用。
3. 平台通过点赞人数、使用人数和使用次数体现应用价值。
4. 运营人员能够下架问题应用。

第一期不负责帮助用户从零制作应用，也不负责修改、更新和版本运营。

## 3. 一期范围

- 从 Hermes Session 对话正文点击受支持的 HTML 地址，在当前 HiTouch 页面打开受控渲染器。
- 从渲染器发起发布，并手动填写应用名称、图标、解决的问题和适用场景。
- 发布时记录作者、来源 Session、来源消息、HTML 地址和 HTML 内容快照。
- 所有发布均创建新应用，初始版本固定为 `1.0.0`。
- 应用列表、关键词搜索、点赞和取消点赞。
- 在线运行已发布 HTML 快照。
- 点赞人数、使用人数和使用次数统计。
- 最小运营管理：查看应用并上架、下架。
- 发布所需的认证、地址白名单、名称唯一性、敏感凭证检查、运行隔离和幂等校验。

## 4. 一期不包含

- 应用中心“新建应用”及 `/hitouch-superpower` 自动创建 Hermes Session。
- Session HTML 渲染器内“修改”。
- 已发布应用“我要修改”。
- “我发布的”作者管理页面。
- 更新已有应用及更新/新建选择。
- AI 自动生成应用信息、相似应用检索及分流建议。
- 版本更新、版本说明、版本历史、版本冲突及回滚。
- 作者自行下架、重新上架或删除应用。
- 多文件成果自动整理为自包含 HTML。
- 完整运营后台中的修改、更新、删除和版本审计。
- 使用趋势、加载失败分析、数据导出或更多榜单。
- 本地 HTML 上传、HTML 下载、历史成果批量导入。
- 多作者、小组维护、所有权转移。
- 面向客户或公网用户开放、客户端嵌入。
- 分类、标签、个性化推荐。
- Skill 中心或应用与 Skill 的长期绑定。

## 5. 核心业务对象

### 5.1 应用

应用是一个可独立运行、可重复解决明确业务问题的 HTML 小工具。第一期只接受已经是单文件、可运行的 HTML，不负责自动合并额外的 JS、CSS、图片或数据文件。

应用至少包含：

- 应用 ID；
- 名称、图标、解决的问题、适用场景；
- 原作者；
- 状态：已上架或已下架；
- 当前版本，第一期固定为 `1.0.0`；
- 当前 HTML 内容快照；
- 来源 Session、来源消息和原 HTML 地址；
- 发布时间；
- 点赞人数、使用人数、使用次数。

### 5.2 作者

- 首次发布时，当前登录用户自动成为原作者。
- 作者由系统写入，发布人不能填写或更换。
- 第一期每个应用只有一名原作者。
- 第一期没有作者管理入口，应用维护由运营人员兜底。

### 5.3 发布快照

- 发布时保存 HTML 内容快照，应用运行使用该快照。
- 原 `site.hitouch.cc` 地址仅作为发布来源，不作为应用的长期运行地址。
- 快照与应用 `1.0.0` 版本关联，第二期可在此基础上扩展不可变版本记录。

## 6. 用户与权限

### 6.1 内部同事

所有已登录内部同事均可：

- 查看和搜索已上架应用；
- 点赞、取消点赞；
- 在线使用应用；
- 从自己可访问的 Hermes Session HTML 渲染器发布新应用。

### 6.2 运营管理员

运营后台复用现有管理员登录和权限体系。第一期管理员可以：

- 查看全部已上架、已下架应用及其作者、来源；
- 上架、下架应用。

第一期不新增前台管理员角色配置，不支持管理员修改、更新或删除应用。

## 7. Session HTML 发布流程

### 7.1 发布入口

Hermes 在 Session 对话正文的 AI 消息中输出 HTML 地址，例如 `https://site.hitouch.cc/{user}/{file}.html`。用户点击受支持地址时：

1. HiTouch 拦截浏览器默认跳转。
2. 不新开窗口或标签页。
3. 在当前页面打开近似全屏的 HTML 渲染器。

第一期至少识别 `https://site.hitouch.cc/` 域名下以 `.html` 结尾的地址。允许域名和路径规则由服务端白名单统一维护。普通网页链接沿用原行为。

Workspace/Artifacts 不是发布入口，本地文件不能直接上传。

### 7.2 Session HTML 渲染器

渲染器以 HTML 实际运行内容为主体，仅提供：

- 返回 Session；
- 发布到应用中心。

渲染器保留来源 Session、来源消息、HTML 地址及本次加载的内容快照。地址失效、加载失败或不符合白名单时，展示失败原因和“返回 Session”，不得退回默认浏览器打开方式。

第一期不提供“修改”。

### 7.3 发布信息

作者点击“发布到应用中心”后手动填写：

- 应用名称：必填，全站唯一；
- 应用图标：必填，一期采用 emoji 或系统支持的图标标识；
- 解决的问题：必填；
- 适用场景：必填。

系统自动写入：

- 当前登录用户为作者；
- 来源 Session ID；
- 来源消息 ID；
- 原 HTML 地址；
- HTML 内容快照；
- 发布时间；
- 版本 `1.0.0`；
- 状态“已上架”；
- 三项统计初始值均为 0。

第一期不由 AI 生成应用信息，不展示更新/新建判断，所有提交均创建新应用。

### 7.4 确认发布

- 发布前展示本次 HTML 预览和应用信息。
- 用户确认后直接上架，对全部已登录内部同事可见，不经过审批。
- 重复点击或网络重试只能创建一个应用。
- 发布成功后返回应用中心并展示成功提示。
- 发布失败时保留已填写信息，允许用户处理后重试。

## 8. 发布校验与失败处理

最终确认发布必须由服务端完成：

1. 校验用户登录状态和发布权限。
2. 校验 HTML 地址协议、域名、后缀及路径白名单。
3. 获取并保存 HTML 内容快照。
4. 确认成果是单个可运行 HTML；多文件成果第一期直接阻止并提示作者先在 Hermes 中整理为单文件。
5. 执行基础敏感凭证检查；发现疑似明文 API Key、Token 等内容时阻止发布。
6. 校验应用名称唯一性。
7. 校验发布幂等键。

名称比较忽略首尾空格、连续空格差异和英文大小写，唯一范围包含已上架和已下架应用。

HTML 必须在平台控制的受限容器或沙箱中运行。前端校验和 AI 判断不能替代服务端校验。

## 9. 应用中心列表与搜索

### 9.1 应用卡片

应用卡片展示：

- 图标；
- 名称；
- 作者；
- 解决的问题；
- 适用场景；
- 点赞人数；
- 使用人数；
- 使用次数；
- “查看详情”入口；
- “使用”按钮。

卡片中的“解决的问题”和“适用场景”各最多显示两行，超出部分以省略号截断。用户可点击应用名称或“查看详情”进入应用详情页；点赞和“使用”仍为独立操作，不进入详情页。

详情页采用上下信息流：顶部先展示点赞人数、使用人数、使用次数，以及点赞/取消点赞和“使用”操作；下方展示图标、名称、作者、版本、发布时间和完整的“解决的问题”“适用场景”。详情页不展示 HTML 预览、截图、来源 Session、原 HTML 地址、联网方式、模型、API、其他技术属性、版本历史或“我要修改”。

### 9.2 排序

- 默认按点赞人数从高到低排序。
- 点赞人数相同时，发布时间更晚的应用在前。

### 9.3 搜索

支持关键词搜索：

- 应用名称；
- 解决的问题；
- 适用场景。

只返回已上架应用。

## 10. 在线使用

- 用户点击“使用”后，在当前 HiTouch 页面打开应用运行渲染器。
- 运行内容来自发布时保存的 HTML 快照。
- 渲染器提供“返回应用中心”。
- 已下架或不存在的应用不得运行。
- HTML 加载失败时展示明确错误，不记录成功使用。
- 第一期不提供“我要修改”。

## 11. 数据指标口径

### 11.1 点赞人数

- 同一用户对同一应用最多保留一个点赞。
- 用户可以取消点赞，取消后点赞人数减 1。
- 再次点赞后恢复计数，不能通过重复请求累计多个赞。
- 数据层对 `(user_id, app_id)` 建立唯一约束。

### 11.2 使用次数

- 用户点击“使用”，且 HTML 快照请求成功并完成渲染器加载后，使用次数加 1。
- 同一次打开过程中的接口重试、重复回调或组件重复挂载只记录一次。
- 用户退出后再次打开并成功加载，可以再次累计使用次数。
- 仅浏览应用列表不计数。

### 11.3 使用人数

- 至少成功使用过一次该应用的去重内部用户数。
- 同一用户多次成功使用同一应用，只计为 1 名使用者。
- 数据层对成功使用关系建立 `(user_id, app_id)` 唯一约束。

### 11.4 数据继承

三项统计均为累计值。第二期增加版本更新、下架和重新上架后，累计值必须继续保留。

## 12. 最小运营管理

运营后台沿用现有框架，第一期至少提供：

- 查看全部已上架、已下架应用；
- 查看应用名称、作者、状态、发布时间和来源；
- 上架、下架；
- 上下架二次确认。

应用下架后：

- 不在公共应用中心展示；
- 普通用户不能通过应用运行入口继续使用；
- 应用信息、HTML 快照和统计数据继续保留。

删除、修改、版本更新、完整操作审计进入二期。

## 13. 页面与功能清单

| 页面/入口 | 一期功能 | 原型路径 |
| --- | --- | --- |
| 工作台 | 进入 Hermes 或应用中心 | `应用中心一期原型/index.html` |
| Session 对话 | 点击受支持 HTML 地址 | `应用中心一期原型/session.html` |
| Session HTML 渲染器 | 查看、返回 Session、发布 | `应用中心一期原型/renderer.html?flow=...` |
| 发布确认 | 手工填写四项信息、预览、确认发布 | `应用中心一期原型/renderer.html?view=publish` |
| 应用中心 | 列表、搜索、点赞、三项统计、使用 | `应用中心一期原型/app-center.html` |
| 应用详情 | 完整说明、基础信息、三项统计、点赞、使用、返回应用中心 | `应用中心一期Demo.html` 的 `app-detail` 视图 |
| 应用运行渲染器 | 运行快照、返回应用中心 | `应用中心一期原型/renderer.html?appId=...` |
| 最小运营后台 | 查看、上架、下架 | 复用现有后台，用户端原型不重复绘制 |

## 14. 数据字段建议

本节用于保证一期数据可平滑升级到二期，具体表结构由研发决定。

### 应用

- `id`
- `name`、`normalized_name`
- `icon`、`problem`、`scenario`
- `author_user_id`
- `status`
- `current_version_id`
- `published_at`
- `like_count`、`usage_user_count`、`usage_count`

### 版本快照

- `id`、`app_id`、`version = 1.0.0`
- `html_snapshot`
- `source_session_id`、`source_message_id`、`source_html_url`
- `published_by`、`published_at`

### 点赞与使用

- 点赞关系：`user_id + app_id` 唯一；
- 成功使用用户关系：`user_id + app_id` 唯一；
- 每次独立打开使用幂等键：`open_id` 唯一。

## 15. 一期验收标准

1. 已登录作者可从 Session 对话正文中的受支持 HTML 地址进入同页渲染器。
2. Session 渲染器只有返回 Session 和发布到应用中心，不提供修改。
3. 作者可填写名称、图标、解决的问题和适用场景；空值不能提交。
4. 发布自动关联作者、来源 Session、来源消息、原地址、HTML 快照和版本 `1.0.0`。
5. 不符合白名单、HTML 获取失败、多文件不受支持、敏感凭证检查失败或快照保存失败时不能创建应用。
6. 归一化后的名称全站唯一，由服务端最终校验。
7. 同一发布请求重复点击或网络重试只创建一个应用。
8. 发布成功后应用直接上架并出现在应用中心。
9. 列表展示规定字段和点赞人数、使用人数、使用次数。
10. 列表按点赞人数、发布时间排序，并支持三个字段的关键词搜索。
11. 同一用户最多保留一个点赞，可取消和再次点赞。
12. 每次独立成功打开增加一次使用次数，同一次打开的重复回调不重复计数。
13. 同一用户多次成功使用同一应用，使用人数只增加一次。
14. HTML 快照在受限运行容器中加载；失败时明确提示且不记录成功使用。
15. 已下架应用不展示、不可运行，但快照和统计保留。
16. 用户可从卡片名称或“查看详情”进入详情页；详情页顶部展示三项统计及点赞、使用操作，下方完整展示说明和基础信息，不展示 HTML 预览、截图或技术属性。
17. 从详情页返回应用中心后保留当前搜索词；不存在、已下架或无权查看的应用不得进入详情页。
18. 一期数据可被二期版本、作者管理和统计能力直接继承。

## 16. 研发评审需确定的技术方案

研发在不改变验收口径的前提下确定：

1. HTML 地址识别、点击拦截、来源消息关联和返回机制。
2. HTML 内容快照的抓取、存储与访问方式。
3. iframe 或其他受限容器的安全隔离策略。
4. 基础敏感凭证检测规则和误报处理。
5. 单文件 HTML 判定及失败提示方式。
6. 发布幂等键和名称唯一约束实现。
7. 成功加载埋点及单次打开 `open_id` 的生成与去重。
8. 点赞、成功使用用户关系和聚合计数的一致性方案。
9. 最小运营后台的复用方式。

## 17. 与二期的边界

一期交付完成的标志是：作者能发布新应用，同事能搜索、点赞并成功使用，平台能统计点赞人数、使用人数和使用次数，运营人员能下架问题应用。

从零新建、修改、更新、版本、作者管理、AI 辅助和完整后台均按《应用中心二期需求文档》实施，不得以一期临时实现替代二期正式设计。

## 18. 原型演示与正式后端责任

### 18.1 主演示入口

一期主演示入口为 `应用中心一期Demo.html`。该文件是一个自包含的单页交互原型，在同一 HTML 内模拟：

```text
HiTouch 首页
→ Hermes 工作台
→ 对话 HTML 预览
→ 发布信息填写与确认
→ 应用中心
→ 应用运行
```

原型刷新后回到首页并恢复种子数据，只用于方便重复演示，不属于正式产品逻辑。正式产品刷新页面后必须从服务端恢复当前用户有权访问的数据，不能清空应用、点赞或使用统计。

### 18.2 前端原型与后端职责映射

| 原型中的模拟行为 | 正式研发必须实现的后端责任 |
| --- | --- |
| JavaScript 内存中的应用数组 | 应用表、版本快照表、状态字段及查询接口 |
| 从 Hermes 对话点击 HTML 地址 | 地址识别、域名与路径白名单、来源 Session ID 和消息 ID 关联 |
| 在同页展示 HTML 模拟内容 | 服务端抓取 HTML 内容快照、文件合法性校验和受限运行容器 |
| 发布表单必填校验 | 服务端重复执行必填、长度、字符和业务规则校验，不能只相信前端 |
| 前端名称查重 | 服务端按归一化名称建立唯一约束，覆盖已上架和已下架应用 |
| 内存中创建 `1.0.0` 应用 | 发布接口原子创建应用、首个版本快照、作者、来源和发布时间 |
| 内存中的已处理发布请求 ID | 客户端生成或服务端下发幂等键；重复提交返回同一发布结果 |
| 内存中的点赞 ID 集合 | 点赞关系表对 `(user_id, app_id)` 建立唯一约束，并提供点赞/取消接口 |
| 每次进入运行视图增加使用次数 | HTML 快照成功加载后上报独立打开事件；同一次打开重复上报必须幂等 |
| 首次使用时增加使用人数 | 成功使用关系对 `(user_id, app_id)` 建立唯一约束并计算去重用户数 |
| 应用中心内存搜索和排序 | 服务端只查询已上架应用，并按名称、问题、场景搜索及规定顺序排序 |
| 刷新恢复初始数据和首页 | 仅为 Demo 行为；正式产品必须持久化并按登录状态恢复数据 |

### 18.3 前后端共同校验原则

- 前端校验用于即时反馈，服务端必须重新校验权限、参数、名称唯一性和幂等性。
- 原型中的作者固定为 Rita；正式产品必须从可信登录态获取用户 ID，不能接受客户端提交作者。
- 原型使用模拟 HTML 内容；正式产品必须运行发布时保存的快照，不能长期直接引用作者的公网源地址。
- 原型不模拟网络失败、快照抓取失败、敏感凭证扫描或数据库异常；正式实现按第 8 节处理。
- 原型中的统计数字仅用于交互演示；正式统计必须由服务端事件和唯一关系计算。
